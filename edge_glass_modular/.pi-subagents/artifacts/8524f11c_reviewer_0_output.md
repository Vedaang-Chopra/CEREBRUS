## Review
- **Correct:** Frozen backbone support exists: CLIP and SentenceTransformer parameters are set non-trainable when `freeze=True` (`src/encoders/vision.py:98-104`, `src/encoders/text.py:63-69`); the default alignment config selects frozen CLIP ViT-L and frozen SBERT MPNet (`configs/pixmo_alignment.yaml:19-35`).
- **Correct:** MRL uses normalized nested prefixes (`src/encoders/mrl.py:35-80`) and is wired into vision/text outputs and alignment losses (`src/encoders/vision.py:223-232`, `src/encoders/text.py:157-169`, `src/models/alignment.py:233-239`, `src/models/losses.py:148-169`).
- **Correct:** Perceiver Resampler is implemented with learned latent cross-attention (`src/encoders/perceiver.py:114-186`) and selectable for vision/audio (`src/encoders/vision.py:111-135`, `src/encoders/audio.py:82-98`). Projection and three fusion strategies are implemented (`src/models/projector.py:63-125`, `src/models/fusion.py:42-137`).

- **Blocker (high):** The configured Phase-1 runner cannot train the alignment model: it passes the entire batch dict as positional `images` (`src/training/trainer.py:53-56`), though `MultimodalAlignmentModel.forward` expects image/audio/text arguments (`src/models/alignment.py:175-184`); it then subscripts a dataclass output (`outputs["loss"]`, `src/training/trainer.py:56`) rather than `.loss`. Thus the CLI launched by `scripts/train_alignment.py:26-35` does not exercise contrastive/MRL training.
- **Blocker (high):** The VLM’s purported latent TRM recursion does not feed the latent state into the output state. It concatenates `[y, z]` (`src/models/trm_qwen_vlm.py:195-207`), but each `TRMLayer` applies causal attention when no mask is supplied (`src/decoders/trm.py:145-153`; called without a mask at `src/models/trm_qwen_vlm.py:199-200`). `y` precedes `z`, so `y` cannot attend to `z`; only `y` reaches logits (`src/models/trm_qwen_vlm.py:209-220`). `trm_norm` and `confidence_threshold` are defined but unused (`:28, :70`). This is repeated shared-layer refinement, not demonstrated latent-state reasoning/adaptive TRM.
- **Blocker (high):** QA padding is included in the training loss. The collator creates `answer_mask` (`scripts/train_vlm_accelerate.py:100-122`) and passes it (`:439-444`), but `QwenVLM.forward` never uses it; labels are raw padded `answer_ids` (`src/models/trm_qwen_vlm.py:116-124, 222-245`).
- **Note (medium):** Actual default VLM training freezes and uses the **separate** `pixmo_alignment.yaml` alignment model (`scripts/train_vlm_accelerate.py:191-245`; default at `:60-61`), where Perceiver is disabled (`configs/pixmo_alignment.yaml:24`). It returns full vision sequences to Qwen, not pooled MRL embeddings (`scripts/train_vlm_accelerate.py:242-245`). Therefore the VLM configs’ Perceiver/MRL declarations are not what the default VLM path uses.
- **Note (medium):** `TRMDecoder` is defined (`src/decoders/trm.py:219-407`), but no supplied config uses `decoder.type: trm`; the VLM runner instead creates Qwen plus `QwenVLM` recursion (`scripts/train_vlm_accelerate.py:258-283`). Validation also bypasses that recursion by calling `inner_model.qwen.generate` directly (`:534-544`).
- **Note (medium):** Fusion is only active with >1 present modality and non-null fusion config (`src/models/alignment.py:90-114,248-260`); every supplied config sets `fusion: null`. It is supported but not configured/exercised here.
- **Note (medium):** MRL is structurally wired, but `losses.sample_single_mrl_dim` is ignored: `AlignmentLoss` is instantiated without passing it (`src/models/alignment.py:169-173`), retaining `True` (`src/models/losses.py:112-126`). Also `AlignmentLoss.forward` references `mrl_losses` even when no MRL dictionaries are supplied (`src/models/losses.py:154-173`), causing an unbound-local error in that case.
- **Note (medium):** The Perceiver variant is defined/configurable (`configs/perceiver_mrl_alignment.yaml:21-45`), but the project’s experiment report records it as failed at random retrieval and attributes this to latent-query initialization (`reports/experiments_report.md:36-60`). It cannot substantiate an effectiveness claim without a newer successful run.
- **Note:** “Frozen SBERT” is configuration-dependent: the Perceiver alignment config selects CLIP text instead (`configs/perceiver_mrl_alignment.yaml:38-45`), while default Pixmo alignment selects SBERT MPNet.
